# Пустые кейсы — реализация и QA, 23.09.2026

## Правило

До появления хотя бы одного доступного материала со статусом `DONE` кейс личный и незавершённый. Загрузка или промежуточные стадии обработки не дают права публиковать кейс или запускать Консилиум. Первый `DONE` снимает ограничения, но не включает общий доступ автоматически.

## Что изменилось

- Можно сохранить кейс без файлов, затем открыть, переименовать, удалить и пользоваться заметками.
- Карточка незавершённого кейса нейтральная (белая в светлой теме), содержит статус и статический замок «Личный». Для обработки показано отдельное состояние.
- В пустом кейсе есть CTA «Добавить материалы», открывающий выбор файлов даже при свёрнутой панели источников.
- Сервер проверяет готовность при публикации. Пустые и обрабатываемые кейсы видит только владелец.
- Удаление последнего готового материала через unlink, замену состава или soft-delete файла снимает общий доступ. Права кейса, файлов, векторов и собственных wiki-страниц обновляются в одной транзакции. Материал в другом общем готовом кейсе остаётся общим.
- История Консилиума и сохранённые позиции не удаляются. Ранее добавленные серверные запреты на запуск LLM/сообщения/итоги остаются в силе.
- Список кейсов, выбор для Консилиума, поиск, ссылки на кейс в цитатах, рейтинг вклада и уведомления учитывают текущую видимость. Исторические уведомления не раскрывают закрытый кейс.
- Готовность обновляется одним общим опросом раз в 5 секунд в активной вкладке; изменения библиотеки обновляют её сразу. Перезагрузка страницы не нужна. Смена доступа сбрасывает кеш поиска; открытый чужой кейс закрывается при отзыве доступа.
- Обновления названия и тегов не отправляют устаревшую приватность или состав источников.
- Нельзя присоединить чужой приватный файл подменой списка материалов. Повторный unlink отсутствующего в кейсе файла не меняет его права.

## Проверки

- Backend: 127 тестов в 16 связанных модулях прошли на отдельном PostgreSQL/pgvector, без обращения к рабочей БД тестовыми фикстурами.
- После оптимизации запроса готовности повторно прошли 76 тестов затронутых API-сценариев. Запрос перебирает источники конкретного кейса и проверяет файлы по первичному ключу.
- Frontend: 1187 passed, 2 skipped; после финальной правки обработчика выбора файлов и опроса — 39 связанных тестов passed.
- Production build прошёл. ESLint без ошибок; осталось прежнее предупреждение `useStatusPolling.ts:88`. Vite сообщает о ранее существовавших крупных chunks.
- В локальном браузере проверены: создание без файла, переименование, белая карточка, empty state, доступность заметок, CTA из свёрнутой панели, состояние STORED, автоматическое появление переключателя после DONE, сохранение личного доступа, ручная публикация, возврат к пустой личной карточке после удаления последнего источника.
- Локальный API отдельно проверен от другого пользователя: опубликованный тестовый кейс виден, после удаления последнего готового источника скрыт. Ошибок в консоли браузера не обнаружено.
- Проверка запрета LLM использует mock конструктора клиента: вызов не происходит. Для проверки состояний использованы синтетические статусы тестового файла; платная генерация в этом прогоне не запускалась.

## Выкат

- Изменения находятся в `stage_first_demo` обоих рабочих репозиториев. Пуш и мерж выполняет владелец проекта.
- При старте API существующие общие кейсы без DONE-источников однократно приводятся к личному состоянию; операция идемпотентна. Данные и история не удаляются.
- Старые кейсы без владельца остаются в БД. Если такой кейс незавершённый, он скрыт; для доступа нужно восстановить владельца. Неизвестный владелец больше не даёт права редактирования всем пользователям.
- Выкатывать backend и frontend вместе. Обновить API и все workers: логика снятия доступа вызывается и из обработки статусов файлов.
- Эти проверки выполнены локально; состояние test/stage/prod после выката этим отчётом не подтверждается.
