# Консилиум: блокировка без готовых материалов

## Правило и реализация

Готовым считается только существующий и доступный пользователю файл со статусом
`DONE`, включённый в текущий `CaseRecord.doc_ids`. Получение файла, OCR, запись
вики и финализация ещё не разблокируют Консилиум. Ошибочные, удалённые и чужие
приватные файлы не учитываются. Создание пустых кейсов осталось доступным.

`GET /api/v1/cases` отдаёт `council.ready_doc_ids` и
`council.processing_doc_ids`. `GET /api/v1/twin/readiness` возвращает такую же
сводку и текущий состав материалов для видимых кейсов. Пока открыт Консилиум,
фронтенд обновляет её каждые 5 секунд; локальные изменения библиотеки запускают
обновление сразу. Скрытая вкладка приостанавливает опрос. Изменения состава в
другом браузере также учитываются, включая добавление первого материала.

Без готовых материалов сервер отвечает `422 council_no_ready_materials` до
создания сессии, записи сообщения и создания LLM-клиента. Это относится к
вступительному раунду, новым сообщениям, смене экспертов и генерации/обновлению
позиций. Готовность проверяется также перед следующим ответом эксперта и перед
сохранением ответа/итога. Если материал удалён во время уже отправленного
запроса к провайдеру, такой запрос нельзя отозвать задним числом: его результат
не сохраняется, следующие вызовы не запускаются.

История сообщений и сохранённые позиции остаются в базе. Заблокированный экран
скрывает диалог, ввод, экспертов и итоги и предлагает добавить материалы через
существующий просмотр кейса. При возвращении готового материала история снова
доступна. В списке выбора пустые/обрабатываемые кейсы видны, но не выбираются;
причина доступна в подписи и подсказке. Тексты добавлены для RU/EN/KK.

## Проверки 23.09.2026

- Backend: 57 тестов успешно — readiness, summary, язык диалога и CRUD кейсов.
  Запуск на отдельном временном PostgreSQL, не на базе приложения.
- Проверены все активные стадии ingestion, FAILED, отсутствие файла, приватность,
  один DONE среди неготовых, отсутствие вызовов LLM и новых сообщений при отказе.
- Проверено удаление последнего материала другим соединением во время ответа и
  генерации итога: следующий эксперт не запускается, прежний итог не теряется.
- Frontend: 1181 тест успешно, 2 пропущены. В том числе автоматические переходы,
  заблокированный выбор, CTA, прекращение стрима, поздний ответ отменённого опроса,
  обновление состава из другого браузера и немедленная реакция на серверный 422.
- Production build успешно; ESLint без ошибок (существующее предупреждение
  `useStatusPolling.ts:88`). Ruff E9/F/I для затронутого кода Консилиума — успешно.
- Ручная проверка в локальном браузере: пустой кейс остаётся в выборе; старый
  Консилиум показывает заглушку; CTA открывает загрузку нужного кейса; добавление
  STORED-файла меняет текст на «Материал обрабатывается»; DONE без перезагрузки
  возвращает ввод и сохранённую историю; удаление материала на вкладке «Итог»
  снова скрывает генерацию и показывает заглушку.
- В ручной проверке использованы отдельные синтетические QA-записи и смена
  статусов, без вызова моделей. Проверено сохранение строки истории после удаления
  материала. Временные записи удалены, существующие материалы не изменялись.

Миграции базы не требуются. Публикуются оба репозитория: сервер должен поддерживать
readiness до установки нового фронтенда. Push и деплой в рамках задачи не выполнялись.
